# 업무 관리

## 실행

`npm start` 실행 후 http://127.0.0.1:3000 에서 엽니다. 프런트엔드는 config.js의 APPS_SCRIPT_URL로 직접 POST 요청합니다. 로컬 JSON 저장소와 CX 탭 가져오기는 화면에서 사용하지 않습니다.

## Apps Script 배포

프로젝트의 Code.gs 코드를 대상 스프레드시트의 Apps Script에 적용하고 웹 앱을 새 버전으로 배포하세요. 웹 앱 접근 설정은 앱 사용자가 호출할 수 있어야 합니다. 배포 URL(/exec)을 config.js의 APPS_SCRIPT_URL에 설정합니다. 현재 기존 URL은 load 요청에 실패 응답을 반환하므로 코드 배포 또는 URL 갱신이 필요합니다.

- 조회: {action: 'load'} → {ok: true, tasks: [...], updatedAt}
- 저장: {action: 'save', tasks: [...]} → {ok: true, updatedAt}
- tasks는 업무별 9개 값의 배열입니다. 순서는 등록, RMS, 작업자, 단계, 완료 & 반영일, 업무제목, 비고, 실 작업 시간, 조정입니다. 기존 11열 배열도 읽을 수 있습니다. 객체 형태의 다른 앱 데이터는 오류로 표시하고 저장을 차단합니다.
- 저장 위치는 Apps Script 코드의 웹앱_CX_업무데이터 시트 A2(JSON), B2(저장 시각)입니다.
- 입력이나 선택 변경 후 0.7초 동안 추가 입력이 없으면 자동으로 서버에 저장합니다. 작업자와 업무제목이 모두 입력되기 전에는 자동 저장을 대기합니다. `저장` 버튼은 자동 저장 실패 시 수동 재시도용입니다.
- 서버 조회에 성공해야 저장할 수 있습니다. 오류 시 로컬 데이터로 서버를 덮어쓰지 않습니다.
- 여러 사용자가 동시에 저장하면 제공한 API 특성상 마지막 저장이 전체 탭에 덮어씁니다.

테스트: npm test

## 업무 공간별 저장소

사이드바 CX / 기업 / 알닷은 같은 스프레드시트의 별도 시트에 저장됩니다. CX는 `웹앱_CX_업무데이터`, 기업은 `웹앱_기업_업무데이터`, 알닷은 `웹앱_알닷_업무데이터`를 사용합니다.

변경된 Code.gs를 기존 Apps Script 프로젝트에 반영한 뒤 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 기존 웹 앱을 업데이트하세요. URL은 유지합니다. 새 시트는 해당 업무 공간 최초 조회 시 생성됩니다. 이전 배포본에서는 데이터 혼합을 막기 위해 기업·알닷 조회와 저장이 차단됩니다. 공간 전환 시 미저장 입력은 현재 페이지에서 보존되지만 새로고침 전에 저장해야 합니다.

## 계정, 권한 및 수정 이력

새 `Code.gs`를 배포하면 첫 접속에서 초기 관리자 계정을 생성합니다. 초기 관리자는 반드시 배포 직후 생성하세요. 이후 관리자는 화면 오른쪽 위 **계정 관리**에서 계정을 추가할 수 있습니다.

- 관리자: 업무 조회·수정, 계정 생성, 수정 이력 조회
- 편집자: 업무 조회·수정, 수정 이력 조회
- 조회자: 업무 및 수정 이력 조회만 가능
- 비밀번호는 Salt가 적용된 반복 SHA-256 해시로 저장되며 원문은 저장하지 않습니다.
- 로그인 세션은 12시간 동안 유효하고 브라우저 탭을 닫으면 클라이언트 토큰이 제거됩니다.
- 저장 시 사용자, 권한, 워크스페이스, 업무, 변경 항목, 변경 전·후 값이 `웹앱_수정이력` 시트에 누적됩니다.
- 계정과 세션은 각각 숨김 시트 `웹앱_계정`, `웹앱_세션`에 저장됩니다. 이 시트의 열 구조를 임의로 변경하지 마세요.

기존 배포에는 인증 API가 없으므로 `Code.gs`를 반영한 뒤 **새 버전으로 재배포**해야 합니다. 기존 URL은 그대로 사용할 수 있습니다.
