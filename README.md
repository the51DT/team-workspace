# 업무 관리

## 실행

정적 호스팅에 index.html, app.js, config.js, styles.css를 배포합니다. 별도 Node.js 서버나 빌드 과정은 필요하지 않습니다. 프런트엔드는 config.js의 APPS_SCRIPT_URL로 직접 POST 요청을 보내며, 로그인 후 업무를 조회하고 수정할 수 있습니다. Code.gs는 정적 호스팅에서 실행하지 않고 Google Apps Script에 배포합니다.

## Apps Script 배포

프로젝트의 Code.gs 코드를 대상 스프레드시트의 Apps Script에 적용하고 웹 앱을 새 버전으로 배포하세요. 웹 앱 접근 설정은 앱 사용자가 호출할 수 있어야 합니다. 배포 URL(/exec)을 config.js의 APPS_SCRIPT_URL에 설정합니다.

- 조회: {action: 'load', workspace: 'cx', token: '로그인 세션 토큰'} → {ok: true, tasks: [...], updatedAt}
- 저장: {action: 'save', workspace: 'cx', token: '로그인 세션 토큰', tasks: [...]} → {ok: true, updatedAt}
- tasks는 업무별 9개 값의 배열입니다. 순서는 등록, RMS, 작업자, 단계, 운영 반영일, 업무제목, 비고, 작업시간, 조정입니다. 기존 11열 배열도 읽을 수 있습니다. 객체 형태의 다른 앱 데이터는 오류로 표시하고 저장을 차단합니다.
- 저장 위치는 Apps Script 코드의 웹앱_CX_업무데이터 시트 A2(JSON), B2(저장 시각)입니다.
- 업무 입력·수정 및 이월 후에는 `저장` 버튼을 눌러 서버에 반영합니다. 작업자와 업무제목은 필수입니다. 삭제는 확인 후 즉시 서버에 저장합니다.
- 서버 조회에 성공해야 저장할 수 있습니다. 오류 시 로컬 데이터로 서버를 덮어쓰지 않습니다.
- 여러 사용자가 동시에 저장하면 제공한 API 특성상 마지막 저장이 전체 탭에 덮어씁니다.

개발용 테스트: 프로젝트 루트에서 `node --test tests/*.test.cjs`를 실행합니다(Node.js 필요). tests 폴더는 테스트용이며 웹사이트 실행에는 필요하지 않습니다.

## 업무 공간별 저장소

사이드바 CX / 기업 / 알닷은 같은 스프레드시트의 별도 시트에 저장됩니다. CX는 `웹앱_CX_업무데이터`, 기업은 `웹앱_기업_업무데이터`, 알닷은 `웹앱_알닷_업무데이터`를 사용합니다.

변경된 Code.gs를 기존 Apps Script 프로젝트에 반영한 뒤 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 기존 웹 앱을 업데이트하세요. URL은 유지합니다. 새 시트는 해당 업무 공간 최초 조회 시 생성됩니다. 이전 배포본에서는 데이터 혼합을 막기 위해 기업·알닷 조회와 저장이 차단됩니다. 공간 전환 시 미저장 입력은 현재 페이지에서 보존되지만 새로고침 전에 저장해야 합니다.

## 계정, 권한 및 수정 이력

로그인 후에만 메인 화면, 업무 및 수정 이력을 조회할 수 있습니다. **로그인** 버튼으로 로그인한 관리자·편집자만 업무를 수정할 수 있습니다. 수정 이력에는 로그인한 수정자의 이름, 시각, 변경 항목과 전·후 값이 기록됩니다.

새 `Code.gs`를 배포한 뒤 **로그인**을 누르면 초기 관리자 계정을 생성할 수 있습니다. 초기 관리자는 반드시 배포 직후 생성하세요. 이후 관리자는 화면 오른쪽 위 **계정 관리**에서 계정을 추가할 수 있습니다.

- 관리자: 업무 조회·수정, 계정 생성, 수정 이력 조회
- 편집자: 업무 조회·수정, 수정 이력 조회
- 비로그인 방문자: 로그인 화면만 접근 가능
- 비밀번호는 Salt가 적용된 반복 SHA-256 해시로 저장되며 원문은 저장하지 않습니다.
- 로그인 세션은 한국시간(Asia/Seoul) 기준 다음 날 00시에 만료됩니다. 기존 24시간 세션도 발급 이후 첫 자정으로 만료 시각을 제한합니다. 같은 브라우저·사이트에서는 탭이나 브라우저를 다시 열어도 복원되며 서버에서 만료를 검증합니다. 로그아웃·비밀번호 변경 시 종료됩니다. 브라우저 사이트 데이터 삭제 또는 비공개 모드 종료 시에는 다시 로그인해야 합니다.
- 저장 시 사용자, 권한, 워크스페이스, 업무, 변경 항목, 변경 전·후 값이 `웹앱_수정이력` 시트에 누적됩니다.
- 계정과 세션은 각각 숨김 시트 `웹앱_계정`, `웹앱_세션`에 저장됩니다. 이 시트의 열 구조를 임의로 변경하지 마세요.

인증 API가 없는 이전 버전을 사용 중이라면 `Code.gs`를 반영한 뒤 **새 버전으로 재배포**해야 합니다. 기존 URL은 그대로 사용할 수 있습니다.
### 조회 시 POST 로그인 요청 오류

이 문구는 이전 `doGet()`의 오류 응답입니다. 최신 `Code.gs` 전체를 Apps Script에 반영하고 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**를 실행하세요. 편집기에서 저장하는 것만으로 기존 `/exec` 배포가 갱신되지는 않습니다. `config.js`의 URL이 해당 배포의 `/exec` 주소인지 확인하세요. 업무·이력 조회는 로그인 세션 토큰을 포함한 POST 요청으로 처리합니다. GET 공개 조회는 지원하지 않습니다.

계정 권한은 관리자·편집자만 지원합니다. 이전 조회 전용 계정은 로그인·세션 사용과 계정 목록에서 제외됩니다. 기존 시트의 계정 행과 수정 이력은 보존합니다.

### 진입 속도

로그인 화면은 서버 요청 없이 즉시 입력할 수 있고, 첫 로그인 요청에서 초기 관리자 생성 필요 여부도 확인합니다. 기존 업무 시트 조회는 저장용 공용 잠금을 기다리지 않습니다. 로그인 복원 중에는 저장된 업무 목록을 표시하지 않습니다. 업무 공간으로 바로 접속하면 업무 조회 요청에서 세션도 함께 확인합니다. 업무 목록은 서버 조회 성공 후 표시하며 브라우저 영구 저장소에서 복원하지 않습니다. 최초 접속은 Apps Script 응답 시간이 필요합니다.

기업은 단계 다음에 STG 반영일을 표시하며, 저장 시 기존 11열 뒤의 12번째 값으로 보관합니다. 기존 9·11열도 조회 가능합니다. 기업·알닷은 조정 열을 화면과 CSV에서 제외하며 기존 저장값은 유지합니다. 모든 공간의 날짜 표기는 운영 반영일입니다. STG 날짜 저장을 위해 최신 Code.gs를 새 버전으로 배포해야 합니다.

비밀번호 생성·변경·로그인은 8~20자로 제한합니다. 업무 및 수정 이력은 세션 토큰을 포함한 POST 요청으로만 조회할 수 있습니다.

## 접속 및 로컬 저장 정책

`file://`로 직접 연 HTML에서는 API 요청을 차단합니다. HTTP(S)로 접속한 localhost, 127.0.0.1 개발 서버와 정적 호스팅 도메인에서는 기존처럼 로그인 후 조회·수정할 수 있습니다. 이 검사는 브라우저 실행 제한이며 API 접근 통제는 서버의 세션·권한 검증이 담당합니다.

업무 목록과 미저장 수정값을 localStorage/sessionStorage에 저장하지 않습니다. 이전 배포 주소별 업무 캐시와 수정값은 같은 브라우저 저장소에서 앱 실행 시 정리합니다. 로그인 토큰 및 안내 팝업 표시 정보는 유지합니다. 업무 공간 이동 중 미저장 내용은 메모리에서만 유지되어 새로고침하면 사라지므로 저장 버튼을 사용해야 합니다. 로그아웃 시 메모리의 업무 목록과 이력도 지웁니다.


## 휴가 일정 캘린더

사이드바 **휴가 일정**(`#schedule`)을 누르면 업무 표 대신 월 캘린더가 열립니다. the51-work 의 캘린더 기능(월 이동·오늘, CX·기업·알닷·전체 탭, 일정 추가·수정·삭제, 일정 끌어서 날짜 변경)을 옮겨 왔고 TO DO LIST·작업시간 표는 뺐습니다.

- 일정 데이터는 **이 브라우저의 localStorage(`workflow-schedule-v1`)에만** 저장됩니다. 서버(Apps Script)에는 저장되지 않아 다른 사람·다른 브라우저와 공유되지 않습니다. 팀 공유가 필요하면 Code.gs에 일정용 시트를 추가해야 합니다.
- 일정 입력창은 구분(CX/기업/알닷)·이름·휴가 일정(연차/오전반차/오후반차/반반차)·시작일·마감일(선택)입니다. 휴가 종류는 `schedule.js` 상단의 `LEAVE_TYPES` 에서 추가·수정합니다.
- 이 화면에서는 업무 검색·새로고침·수정 이력 버튼이 숨겨집니다.
- 대한민국 공휴일은 API 없이 `schedule.js` 안에서 계산해 날짜 칸에 빨간 글씨로 표시합니다. 신정·삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절은 고정 날짜, 설날·추석·부처님오신날은 브라우저 내장 한국식 음력(`Intl` dangi)으로 계산하고, 대체공휴일도 규칙대로 계산하므로 연도 제한이 없습니다. 선거 등 임시공휴일은 계산할 수 없어 `TEMP_HOLIDAYS` 에 직접 추가해야 합니다. 현재 공휴일 지정 법령 기준이라 이후 법이 바뀌면 코드 수정이 필요합니다.

업무 목록의 조회 가능 월은 한국시간 기준 이전 달·이번 달·다음 달입니다. 범위 밖 월 이동과 다음 달을 넘어가는 이월은 제한합니다. 서버는 기존 전체 데이터를 유지하며, 화면 표시만 제한하므로 저장 시 범위 밖 월 데이터도 보존됩니다. 이 제한은 API의 데이터 접근 권한 제한이 아닙니다.
